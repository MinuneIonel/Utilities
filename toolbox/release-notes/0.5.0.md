# What's new in 0.5.0

**Saving**
- Rendering again replaces the file that Save node wrote last time, instead of adding "name (2)", "name (3)"… It never replaces a file it didn't write: then it adds a number, and replaces that one next time.
- A Save node with a folder has a new setting, **If the file exists**: *Replace my last save*, *Keep both (add a number)* or *Skip it*.

**Clearer buttons**
- The main button says **Render & save** when there's a Save node. A dot on it means a result is out of date.
- Nodes that only run on Render (Encode video, Cut audio, the PDF tools, Save…) have a dashed top edge and say "Runs on Render". Their new **Run** button shows the result without saving anything.
- The top bar says **New graph**, **Open graph** and **Save graph**, and a Save node's own button says **Save again** once it has saved.

**Safer graph files**
- Opening a graph from someone else that points to files on your computer now asks first: **Use them** or **Open without files**. The files you dropped in before keep working.

**Fixes**
- Encode and Save show "Out of date" when something before them changed since the last Render, instead of looking current.
- Moving the playhead no longer makes Render encode and save the same video again.
- Thumbnails come back after New then Undo.
- MP4 and MOV videos made on Linux get AAC sound, which plays everywhere.
- Number boxes pull a typed value back into range.
- Cut audio and Split into clips keep the source's quality when the format stays the same.
- Broken graph files (loops, repeated nodes, unknown nodes) are repaired and say what was fixed, instead of failing quietly.
- A link's download can be stopped with **Stop download**.
- ⌘R while typing a link uses the link you typed.
- Images dropped onto an Image file node go into that node.
- On Windows, big videos are no longer copied before ffmpeg reads them.
- No error after pressing Cancel.
